# IDML 헤드리스 렌더러 작업 인수인계

기준: 2026-11-15 · 마지막 구현 커밋 `03bacb4a`

## 목표와 현재 범위

기사 내용을 IDML 지면에 채우고, 렌더 결과를 에이전트가 확인해 수정·재렌더하는
자동화가 최종 목표다. 현재 구현된 것은 첫 단계인 **IDML → PNG/PDF 헤드리스
렌더링**이다. IDML 기사 편집과 에이전트 피드백 루프는 아직 구현되지 않았다.

DesignCraft의 문서 모델, 글꼴, 조판, IDML 가져오기, 이미지, PNG/PDF 렌더 코드를
사용한다. 데스크톱·웹 앱, 편집 엔진, MCP 및 관련 없는 변환 앱은 제거했다.

## 저장소와 작업 방식

- 개인 포크: [Jaiwooyu/designcraft](https://github.com/Jaiwooyu/designcraft).
- 로컬 `main`은 `fork/main`을 추적한다. `origin`은 원본 `storytold/designcraft`다.
- 사용자 요청에 따라 PR 없이 개인 포크 `main`에 직접 반영한다. 원본 저장소에는
  푸시하지 않는다.
- 작업 전 [AGENTS.md](../AGENTS.md), [ROADMAP.md](../ROADMAP.md),
  [알려진 문제](gaps.md)를 확인한다. 라이선스·저작권·출처 고지는 유지한다.

## 빌드와 실행

Rust 1.95 이상이 필요하다. 서버에 한글을 지원하는 고딕체를 설치한다. 저장소에는
새 폰트 파일이나 사용자의 신문 지면을 커밋하지 않는다.

```sh
cargo build --release
./target/release/idml-render \
  --in input.idml \
  --png-dir output \
  --pdf output/layout.pdf
```

`--fallback-font 'Noto Sans CJK KR'`로 설치된 대체 글꼴을 지정할 수 있다. 지정하지
않으면 설치된 한글 고딕 계열을 순서대로 찾는다. `--scale 2`는 PNG를 포인트당
2픽셀로 출력한다. PNG는 도련을 포함하고 PDF는 기본 설정상 도련과 재단선을 포함하지
않는다. 상세 옵션과 제한은 [렌더러 가이드](idml-render.md)를 참고한다.

링크 이미지는 IDML 옆이나 `Links` 폴더에 둔다. 문서 글꼴 폴더도 지원한다. 입력과
각 링크 파일은 256 MiB로 제한하고, 링크와 문서 글꼴은 IDML 폴더 밖으로 나가지
못하게 검사한다. 누락 링크·글꼴 대체·일부 텍스트 넘침은 stderr 경고로 나온다.

## 코드 위치

- `apps/idml-render/src/main.rs`: 인자 처리, 입력과 링크 읽기, PNG/PDF 출력.
- `apps/idml-render/src/fonts.rs`: 누락 글꼴 대체.
- `crates/idml`, `crates/doc`, `crates/compose`: IDML 가져오기, 문서 모델, 조판.
- `crates/fonts`, `crates/images`, `crates/render`, `crates/pdf`: 글꼴, 이미지,
  래스터 및 PDF 출력. `crates/geom`, `crates/color`는 공통 기반이다.
- `apps/idml-render/tests/render.rs`: 합성 문서의 PNG/PDF 출력과 입력 덮어쓰기 방지.

## 확인된 결과와 한계

사용자가 제공한 12·13면 IDML과 같은 폴더의 PDF를 기준으로 확인했다. IDML에는
3페이지가 있으며, 리팩터링 전후 같은 대체 글꼴로 출력한 PNG 3장은 SHA-256이
일치했다. 이는 **기존 DesignCraft 렌더와의 일치**이며 기준 PDF와 완전히 일치한다는
뜻은 아니다. 실제 사용자 파일과 PDF는 저장소 밖에 두고 테스트에 커밋하지 않는다.

- 원본 글꼴을 사용할 수 없는 환경에서 Apple SD Gothic Neo로 대체하면 기존 490자에서
  25자로 텍스트 넘침 경고가 줄었다. 글꼴마다 결과가 달라진다.
- 기준 PDF의 12면 하단 광고는 패키지의 원본 링크 파일이 없어 렌더에서 빠졌다.
  사용자 설명상 실제 워크플로에서는 이미지가 제공될 예정이다.
- 이 Mac에서 해당 3페이지를 PNG 3장과 PDF로 함께 출력한 단일 실행들은 약
  **2.6~3.4초**였다. Linux 서버, 24면 문서, 동시 요청 및 병렬 처리 성능은
  측정하지 않았다. 24면 약 21~27초나 4개 병렬 작업 약 7~15초는 단순 추정으로,
  실제 벤치마크 결과가 아니다.
- 한 실행에서 문서를 읽고 페이지를 순회해 PNG를 만들고 PDF를 출력한다. 페이지별
  병렬 처리나 분산 서버는 구현·검증되지 않았다. 내부 라이브러리는 이미 병렬
  처리를 사용할 수 있으므로 작업 수를 늘리기 전에 CPU·메모리·I/O를 측정한다.
- IDML의 모든 기능이 재현되는 것은 아니다. 배치 PDF의 일부 비기본 크롭과 부모
  페이지의 넘침 경고는 추가 작업이 필요하다. [알려진 문제](gaps.md)를 확인한다.

## 이어서 할 일

1. 실제 Linux 서버에 한글 고딕체를 설치하고, 24면 IDML과 링크 이미지를 준비해
   렌더 시간·최대 메모리·출력 정확도를 측정한다. PNG만, PDF만, 둘 다를 분리해
   측정하고 환경·반복 횟수·글꼴을 기록한다.
2. 페이지별 병렬 처리의 효과를 기준선과 비교한다. 파일 읽기와 폰트 초기화 비용,
   PDF 병합의 정확성, 메모리 사용량 및 내부 병렬 처리와의 경쟁을 함께 검증한다.
3. 기사 프레임 식별과 IDML 텍스트 교체 방식을 설계한다. 원본 스타일과 ZIP 구조를
   보존하고, 텍스트 넘침을 기계가 읽을 수 있게 보고하는 것이 필요하다.
4. 렌더 → 시각 검토 → 수정 → 재렌더 루프를 구현한다. 실제 문서의 기준 PDF와
   비교하되 사용자 파일과 이미지가 저장소에 들어가지 않도록 한다.

커밋 전 `cargo xtask ci`를 실행한다. 마지막 전체 로컬 검사는 포맷, Clippy, 테스트,
에셋 출처, 의존성 계층 및 남은 라이브러리의 WASM 검사를 통과했다. 포크의 원격 CI와
Linux 실행 결과는 별도로 확인해야 한다.
